# Screenshots Plan

This plan defines the minimum public-safe screenshots to capture before using
the repository in portfolio posts, README updates, or release packaging.

## Goals

- Show the real desktop workflow without exposing secrets or private media.
- Keep screenshots consistent across GitHub README, releases, and CV links.
- Capture only screens that demonstrate product value, not internal clutter.

## Required Screens

1. Queue view with 2-3 example jobs in different states.
2. Settings view with Groq key field visibly masked.
3. Completed job detail with transcript preview and export actions.
4. Empty-state screen that shows first-run usability.

## Capture Rules

- Use neutral sample filenames and safe transcript content.
- Remove any real API keys, local usernames, or private folder names.
- Prefer Windows 11 light or dark theme consistently within one set.
- Keep the app window cropped tightly; avoid noisy desktop background.

## Packaging Targets

- README hero screenshot
- Release note attachment set
- Social preview candidate
- CV / portfolio reference images
