## Bundling for Release

### Windows Installer

The project includes **NSIS** and **MSI** installer generators via Tauri's bundler.

#### Configuration

**File:** `src-tauri/tauri.conf.json`

Current settings (Tauri 2):
```json
{
  "bundle": {
    "active": false
  }
}
```

**Note:** Bundling is currently disabled to match Tauri 2 API. To enable, use Tauri's bundling commands directly:

```powershell
# Enable bundling via CLI
cargo tauri build
```

**For future optimization**, you can add custom bundler config when needed:
- NSIS configuration for Windows installer
- FFmpeg sidecar binary management
- Resource bundling (rnnoise models)

See Tauri 2 [Bundle Configuration](https://tauri.app/en/develop/guides/distribution/creating-installers/#tauri-config) for latest syntax.

#### Building the Bundle

```powershell
cd src-tauri

# Build Tauri bundle (creates NSIS installer)
cargo tauri build
```

**Output locations:**
- NSIS installer: `src-tauri/target/release/bundle/nsis/*.exe`

**Default installer features** (generated by Tauri):
- User-friendly installer UI
- Custom install path support
- Uninstall via Windows "Add or remove programs"
- Auto-creates Start Menu shortcuts
- Extracts app files to `AppData/Local/`

### Sidecar Binaries (Future Implementation)

⚠️ **Sidecar management is not yet configured.**

When FFmpeg/ffprobe integration is complete (Phase 2+), sidecars will be bundled as:
- Standalone executables downloaded during build
- Extracted to installer bundle
- Placed in `AppData\Local\VideoTranscriber\bin\` on user's machine
- Verified by SHA256 hash before execution

Configuration will be added to `tauri.conf.json` under `externalBin` when needed.

### Resources (Future Implementation)

Rnnoise model for noise reduction:
- Required: `../rnnoise-models/` directory in workspace root
- Will be included in bundle as resource
- Accessible to app via `$APPDATA/VideoTranscriber/rnnoise-models/`

Configuration will be added to `tauri.conf.json` under `resources` when needed.

## GitHub Actions Workflow

### Automatic Release on Tag

**Trigger:** Push a version tag

```powershell
# Create and push version tag
git tag v0.2.0
git push origin v0.2.0
```

**Workflow:** `.github/workflows/release-windows.yml`

Automatically:
1. Checks out code
2. Installs Rust, Node.js
3. Runs all tests & linting
4. Builds Tauri bundle (NSIS installer)
5. Creates GitHub Release
6. Uploads NSIS installer
7. Generates release notes from commits

### Manual Trigger

Go to **Actions** → **Release — Windows** → **Run workflow**

Inputs:
- **Version:** e.g., `0.1.0` (optional, auto-detected from tag)

Output: Artifacts uploaded to **Actions** tab (30-day retention)

### Checking Workflow Status

```bash
# See last runs
gh run list --workflow=release-windows.yml

# See details of specific run
gh run view <RUN_ID> --log
```

## Code Signing & Security

### Windows Code Signing (Optional)

⚠️ **This requires manual setup by user. See [USER ACTIONS](#user-actions-required) below.**

Tauri supports signing NSIS/MSI installers with a certificate.

#### Prerequisites
- Authenticode certificate (from trusted CA like Sectigo, DigiCert)
- Private key (.pfx file with password)

#### Configuration

**In `src-tauri/tauri.conf.json`:**
```json
{
  "bundle": {
    "windows": [
      {
        "certificateThumbprint": "YOUR_CERT_THUMBPRINT_HERE",
        "signingIdentity": "Your Organization Name",
        "timestampUrl": "http://timestamp.sectigo.com"
      }
    ]
  }
}
```

#### Obtain Thumbprint

```powershell
# List certificates in Windows certificate store
Get-ChildItem Cert:\CurrentUser\My | Format-Table Thumbprint, Subject

# Find your signing cert and copy Thumbprint
```

#### Environment Variables (GitHub Actions)

To sign in CI, set GitHub Actions secrets:

1. Go to **Settings** → **Secrets and variables** → **Actions** → **New repository secret**
2. Add:
   - `CERTIFICATE_PFX_BASE64`: Your .pfx file encoded as base64
   - `CERTIFICATE_PASSWORD`: The private key password

3. In workflow, install cert before build:
```yaml
- name: Install signing certificate
  if: github.event_name == 'push' && startsWith(github.ref, 'refs/tags/')
  shell: powershell
  run: |
    $pfxBytes = [System.Convert]::FromBase64String("${{ secrets.CERTIFICATE_PFX_BASE64 }}")
    $certPath = "cert.pfx"
    Set-Content -Path $certPath -Value $pfxBytes -AsByteStream
    
    $password = ConvertTo-SecureString -String "${{ secrets.CERTIFICATE_PASSWORD }}" -AsPlainText -Force
    Import-PfxCertificate -FilePath $certPath -CertStoreLocation Cert:\CurrentUser\My -Password $password
    
    Remove-Item $certPath
```

### No Code Signing (Default)

If you skip signing:
- Windows 10/11 may show "Unknown publisher" warning
- User can still install (click "More info" → "Run anyway")
- No impact on functionality

**This is fine for open-source / testing releases.**

## Auto-Update Configuration

⚠️ **Auto-update is not yet active.** See [USER ACTIONS](#user-actions-required) below.

When ready to enable auto-updates:

### 1. Generate Signing Keys

```powershell
cd src-tauri
cargo tauri signer generate --ci
# Outputs:
# - private key
# - public key (save this)
```

### 2. Update Configuration

**In `src-tauri/tauri.conf.json`:**
```json
{
  "updater": {
    "active": true,
    "dialog": true,
    "pubkey": "YOUR_PUBLIC_KEY_HERE",
    "endpoints": [
      "https://updates.example.com/releases/latest.json"
    ]
  }
}
```

### 3. Prepare Update Server

The server must respond with JSON manifest:

```json
{
  "version": "0.2.0",
  "notes": "Bug fixes and performance improvements",
  "pub_date": "2025-05-15T12:30:00Z",
  "platforms": {
    "windows-x86_64": {
      "signature": "...",
      "url": "https://releases.example.com/VideoTranscriber_0.2.0_installer_x64.exe"
    }
  }
}
```

See [Tauri Updater Documentation](https://tauri.app/en/develop/guides/distribution/updater/) for details.

### 4. Sign and Release

```powershell
cd src-tauri

# Build and sign
cargo tauri build -- --sign-updates-key YOUR_PRIVATE_KEY
```

## Windows Troubleshooting

### Build Fails: "Microsoft Visual C++ 14.0 is required"

**Solution:**
```powershell
# Install Visual Studio Build Tools
# Download from: https://visualstudio.microsoft.com/visual-cpp-build-tools/

# Or use WSL2 for Linux build environment
wsl
cargo build --release
```

### FFmpeg Download Fails

**Symptom:** "Failed to download sidecar binary ffmpeg"

**Solutions:**
1. Check internet connection
2. Check if URL is still valid (GyanD releases might move)
3. Download manually and place in:
   - `src-tauri/bin/ffmpeg.exe`
   - `src-tauri/bin/ffprobe.exe`
4. Update `tauri.conf.json` with correct SHA256

### Installer Won't Uninstall

**Solution:**
```powershell
# Remove via Windows Registry
Remove-Item "HKCU:\Software\Microsoft\Windows\CurrentVersion\Uninstall\VideoTranscriber"

# Or use Windows Settings:
# Settings → Apps → Apps & features → VideoTranscriber → Uninstall
```

### App Crashes on Startup

**Check logs:**
```
%APPDATA%\VideoTranscriber\logs\
```

**Common issues:**
- FFmpeg/ffprobe not found → Check bundle extraction
- API key not accessible → Check Credential Manager
- Database corrupt → Delete `%APPDATA%\VideoTranscriber\db.sqlite`

## User Actions Required

The following require manual steps (not automated):

### 1. **Code Signing Certificate** (Optional)
- Required if you want to avoid "Unknown publisher" warning
- Need to purchase Authenticode certificate from trusted CA
- Store `.pfx` file securely, never commit to repo
- Set GitHub Actions secrets for CI/CD signing

**Action:** If desired, follow [Code Signing & Security](#code-signing--security) section.

### 2. **Auto-Updater Server** (When Ready)
- Need external server to host release manifests and updated .exe
- OR use GitHub Releases as CDN (simple approach)
- Generate and safeguard updater private key

**Action:** When feature is ready, follow [Auto-Update Configuration](#auto-update-configuration) section.

### 3. **FFmpeg Sidecar Updates**
- Monitor [GyanD/codecs-and-media-frameworks](https://github.com/GyanD/codecs-and-media-frameworks/releases) for new versions
- When updating, recompute and verify SHA256 hash
- Test extraction and execution on target machine

**Action:** When new FFmpeg version available, update `tauri.conf.json`.

### 4. **Notarization** (macOS, Not Applicable Yet)
- macOS requires notarization for apps distributed outside App Store
- This is macOS-specific, not needed for Windows
- Include when macOS support is added

## Build Profile Optimization

For faster builds during development:

```toml
[profile.dev]
opt-level = 0
debug = true
split-debuginfo = "packed"

[profile.release]
opt-level = 3
debug = false
lto = true
codegen-units = 1
strip = true
```

**Note:** Release builds are slower but produce optimized, smaller binaries.
