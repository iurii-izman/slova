# VideoTranscriber — Техническая спецификация проекта

## Контекст и требования

**Задача:** настольное приложение для пакетной транскрибации русскоязычных MP4 видео в текст.

**Окружение:**
- Ноутбук: Ryzen 3, 8 GB RAM, Windows 11
- Дискретной GPU нет — локальные модели отпадают
- Интернет стабильный, автономность не нужна
- Объём: 10–50 видео, несколько часов суммарно
- Качество звука: среднее, есть фоновый шум
- Приоритеты: **Скорость > Точность (RU) > Стоимость**

---

## API: Groq Whisper Large v3 Turbo

| | Groq | OpenAI | Deepgram | AssemblyAI |
|---|---|---|---|---|
| Скорость | **216x** (~8 сек/30 мин) | ~10x | ~120x | ~50x |
| Русский | ✅ отлично | ✅ | ⚠️ хуже на шуме | ✅ |
| Цена | **$0.04/ч** | $0.36/ч | $0.26/ч | $0.15/ч |
| Лимит файла | 100 MB | 25 MB | 2 GB | без лимита |

Groq выигрывает по скорости в 2–5 раз у всех конкурентов.  
Лимит 100 MB решается конвертацией аудио перед отправкой (см. Pipeline).

---

## Стек: Tauri + Solid.js + Rust

Нативный паттерн из replyline — нет кривой обучения.  
Rust даёт параллельную очередь через `tokio`, бинарь 10–15 MB.

---

## Pipeline обработки

```
MP4 (200 MB)
  → ffprobe валидация
  → ffmpeg: Opus mono 16kHz 32kbps (~7 MB за 30 мин)
  → [если >100 MB] fallback-чанкинг по тишине с overlap 5–10 сек
  → Groq API (whisper-large-v3-turbo)
  → verbose_json (текст + таймкоды)
  → video.txt рядом с исходником
  → [опционально] Groq Llama: чистка пунктуации
```

**Команда ffmpeg с шумоподавлением:**
```bash
ffmpeg -i input.mp4 \
  -vn -ac 1 -ar 16000 \
  -af "arnndn=m=rnnoise-models/cb.rnnn" \
  -c:a libopus -b:a 32k output.opus
```

- **Opus vs MP3/WAV:** в 2–3 раза меньше при том же качестве для STT → быстрее аплоад
- **arnndn** — нейросетевой фильтр шума в ffmpeg, снижает галлюцинации модели на среднем звуке
- **Без чанкинга** (в норме): 100 MB лимит покрывает файл целиком → сохраняется контекст → лучше пунктуация
- **Параллельность:** `Semaphore(3)` — оптимум под Groq free tier (30 rpm). 5 файлов × 30 мин ≈ 45–60 сек суммарно

## Запрос к Groq API

```json
{
  "model": "whisper-large-v3-turbo",
  "language": "ru",
  "response_format": "verbose_json",
  "temperature": 0,
  "prompt": "Это запись на русском языке. Говорит один человек."
}
```

- `temperature=0` — детерминированный вывод, меньше случайных ошибок
- `prompt` — резко снижает галлюцинации и улучшает пунктуацию на шумном звуке
- `verbose_json` — возвращает текст + таймкоды сегментов (нужно для SRT и склейки чанков)

## Архитектура очереди (Rust / tokio)

Каждый файл — state machine:

```
queued → extracting → uploading → transcribing → done
                                               → error → [retry]
```

- `Semaphore(3)` — 3 параллельных задачи
- Exponential backoff на 429/5xx — без этого при очереди из 5 файлов гарантированно словишь rate limit
- Кэш по хешу файла — если файл уже обрабатывался, пропускаем
- ffprobe перед стартом — битый файл или MP4 без аудиодорожки → мгновенная ошибка, не тратим время

---

## Fallback-чанкинг (если файл >100 MB после конвертации)

1. `ffmpeg silencedetect` — находит точки тишины
2. Нарезка с overlap 5–10 сек между чанками
3. Параллельная отправка чанков
4. Склейка по таймкодам из `verbose_json`, дедупликация в зонах overlap

---

## UI — обязательные элементы

- Drag & Drop зона (несколько файлов)
- Очередь с состояниями и прогрессом на каждый файл
  - Аплоад: реальный % (reqwest stream)
  - Транскриб: indeterminate (Groq не отдаёт прогресс внутри запроса)
- Inline-превью + редактирование текста
- Кнопка Retry на ошибках
- Настройки: язык, формат вывода (txt / srt / json), лимит параллельности
- API ключ в OS keychain (`keyring` crate)

---

## Хранение данных

**SQLite** в `%APPDATA%` — история всех задач: путь к файлу, статус, путь к результату, время, ошибки.  
При перезапуске приложения видно что уже обработано, можно открыть старый результат.

---

## Постобработка (опционально, +~1 сек)

Прогнать транскрипт через `llama-3.1-8b-instant` на Groq с промптом на чистку пунктуации.  
Groq тот же, дополнительных интеграций ноль.

## MVP — план по дням

**День 1 — ядро:**
- Tauri init + Solid.js UI-скелет
- Rust команда `extract_audio` через ffmpeg-sidecar
- Тестовый запрос к Groq API → текст в консоль
- ffprobe валидация

**День 2–3 — рабочий инструмент:**
- Solid.js очередь с состояниями
- Tauri events для прогресса в UI
- Параллельность через tokio Semaphore(3)
- Автосохранение `.txt` рядом с видео
- Inline-превью текста
- Exponential backoff + Retry
- Keychain для API ключа

**После MVP:**
- SQLite история
- Экспорт SRT/JSON (таймкоды уже есть в `verbose_json`)
- Fallback-чанкинг для больших файлов
- Постобработка через Groq Llama
- Кэш по хешу файла
- Auto-update (Tauri Updater)
