DATABASE SCHEMA
================================================================================

Tables created:
- jobs (id, source_path, display_name, size_bytes, content_hash, created_at,
        finished_at, state, state_payload, output_path, settings_json,
        attempts, error_message, error_code)
- transcripts (job_id, plain_text, segments_json, edited_text, updated_at)
- cache (cache_key, job_id, created_at)
- settings (key, value)

Indexes:
- idx_jobs_state ON jobs(state)
- idx_jobs_created ON jobs(created_at DESC)
- idx_jobs_hash ON jobs(content_hash)
- idx_cache_job ON cache(job_id)

Location:
- Windows: %APPDATA%/VideoTranscriber/transcriber.db
- macOS: ~/Library/Application Support/VideoTranscriber/transcriber.db
- Linux: ~/.local/share/VideoTranscriber/transcriber.db

================================================================================
SECURITY FEATURES
================================================================================

✅ Implemented:
- API keys stored in OS keychain (never in DB or logs)
- Keyring uses native encryption (DPAPI on Windows)
- API key validation before storage
- No hardcoded secrets in code
- SQLite in user-owned app data directory

❌ Not implemented (Phase 3+):
- FFmpeg execution (no shell injection risks)
- Rate limiting (will be in Groq client)
- User authentication (not needed for desktop)
